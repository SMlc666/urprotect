# Jump-table ownership: next substantive slice

**Scope:** read-only research for implementation-plan Phase 2, items 10–12. This note does not claim code/test/evidence changes or a verification result. Findings below distinguish repository facts from design inferences.

## Result

The existing bounded signed-relative jump-table path proves a selected dispatch’s index bound, table byte range, entry decoding, and in-function target closure. It does **not** prove table ownership. Despite that, the resolver’s proof string and the semantic-plan factory currently label the fixture table `SelectedFunctionPrivate` and `InPlace`. The native fixture’s table is actually a global/default-visible dynamic symbol (the evidence checker expects it as `NOTYPE`); this is not proof that a second user exists, but it certainly is not proof that only the selected function can reach it.

The private-table positive is safe only under its currently assumed private ownership. A shared/ambiguous-table positive cannot be implemented end-to-end with the current layout contract: there is no ambiguity state or owner-proof record, no copied-table output placement/edit path, and no persisted selected table-reference binding for rehydration to retarget. The smallest meaningful positive is therefore **one bounded shared-table copy-and-retarget vertical slice**, preceded by a narrow structural owner-evidence/layout-contract prerequisite—not another rejection-only negative. Keep the existing external-table four-negative PASS scoped as fail-closed evidence; it does not close this gap.

## 1. Confirmed repository facts: current owner data path

1. **Selected-function resolver.** `Aarch64JumpTableResolver.TryResolve` consumes the selected function’s decoded instructions, matches the adjacent `ADRP; ADD; LDRSW; ADR; ADD; BR` relative-table shape, requires an adjacent unsigned `CMP`/`B.HI` bounds proof, rejects an intervening checked-index write, caps the bounded set at 65,536, and reads exactly the file-backed table range through `LoadMap` (`src/UrProtect.Core/Aarch64Semantics/Aarch64JumpTableResolver.cs:96-120,150-217`). It validates each entry’s executable-PT_LOAD mapping and requires each target/default to be inside the selected function’s decoded closure (`:228-263`). It does not query symbols, relocations, visibility, or any other function/table users. Its output has table/base/range/entry/bounds/default/producer addresses and a free-text `Proof`, but no ownership evidence field (`:13-94,265-283`). The proof text nevertheless asserts “selected-function private” (`:283`).
2. **Factory’s ownership and rewrite values.** `Aarch64SemanticPlanFactory.AddJumpTableExtensions` creates a table identity/range, identity-maps the table and entries, binds exact entry targets and default target, then hard-codes `ownership: SelectedFunctionPrivate`, `rewritePolicy: InPlace`, and `outputRange: tableRange` (`src/UrProtect.Core/SemanticPlanning/Aarch64SemanticPlanFactory.cs:1296-1362`). `SourceInstruction` identifies the indirect branch, not a persisted list of the table-base reference sites. `tests/UrProtect.Core.Tests/Application/FunctionProtectionTests.cs:154-180` asserts those ownership/policy values; it tests the current assertion, not ownership proof.
3. **Snapshot.** `SemanticJumpTableExtension` already has `SelectedFunctionPrivate`, `Shared`, `External`, and `RuntimeOwned` values plus `InPlace`, `CopiedAndRetargeted`, `PreservedAtOriginalAddress`, `StableVeneer`, and `RuntimeTranslation` policies (`src/UrProtect.Core/SemanticPlanning/SemanticPlanExtensions.cs:35-50`). The extension carries range, encoding, bases, source branch, targets, entries, ownership, policy, and an optional output range, but no owner-evidence structure or explicit table-reference producer/site bindings (`:59-150`). The canonical codec serializes the owner/policy values and entry rows (`SemanticPlanSnapshotEncoding.cs:419-470`); decoding validates enum values and reconstructs them (`SemanticPlanSnapshotDecoding.cs:1143-1264`); snapshot validation checks ranges, widths, bounds, entry identities, and enum validity (`SemanticPlanSnapshotValidation.cs:611-679`). Serialization preserves the factory’s claim; it does not establish that claim. In particular, `ProducerAddresses` from the resolver are not part of the jump-table extension encoding.
4. **Layout request, edits, and materializer.** Rehydration validates that the source table range maps through the structural `LoadMap`, then passes the table range, target base, encoding, **rewrite policy**, and entries to `ElfLayoutJumpTableEditRequest` (`src/UrProtect.Core/Application/Rehydration/GenericRehydrationEngine.cs:1042-1093`). The request has no ownership field, clone output range, or table-reference retarget requests (`src/UrProtect.Core/ElfLayout/ElfLayoutContracts.cs:354-363`). `ElfLayoutPlanner.BuildJumpTableEdits` rejects every policy except `InPlace`, verifies the original source mapping and address map, computes entry encodings from output targets/bases, and emits `JumpTableEntry` edits at the source table’s file offsets (`ElfLayoutPlanner.cs:2672-2715,2724-2825`). It does not copy a table. Layout schema-2 evidence has per-entry bindings and edits (`ElfLayoutContracts.cs:319-339,396-425`); the materializer checks edit/binding/output-byte one-to-one consistency (`ElfLayoutMaterializer.cs:1659-1695,1841-1862`), not table ownership.
5. **Code reference retargeting.** The live protection emitter still has the resolution’s in-memory `ProducerAddresses`; for the current no-copy case it re-encodes matching `ADRP`/`ADR` producers to the existing table base or target base (`src/UrProtect.Core/Application/Protection/FunctionProtectionCodeEmitter.cs:1053-1083`). The shared snapshot/layout contract does not persist a table-copy destination/reference binding. A copied table would need to retarget the selected function’s complete table-address producer expression (including its low-12 `ADD` or other addressing pieces), while keeping all unselected references at the original table. Any generated instruction must stay behind `Aarch64InstructionEncoder`, per `.trellis/spec/backend/quality-guidelines.md:38-49`.

### Native fixture/spec mismatch to keep explicit

- The current source-built fixture defines `.global urp_jump_table` in `.rodata` (`native/urprotect-runtime/host_context_jump_table_fixture.S:73-81`) and uses it from one demonstrated dispatch (`:10-26`). It does **not** demonstrate a second consumer.
- The independent positive checker binds `urp_jump_table` and the case symbols as `GLOBAL DEFAULT`, and explicitly expects the table to be dynamic-symbol `NOTYPE` (`scripts/check-indirect-control-evidence.py:816-849`). It verifies table bytes, targets, edits, and per-target layout bindings; the retained criteria describe those facts, not an owner proof (`.trellis/tasks/10-06-indirect-control-jump-tables/prd.md:50-52`).
- Therefore the child PRD is right to keep ambiguous ownership open (`prd.md:48,52`), and its four-negative external row is explicitly fail-closed only. The unsupported claim is the current resolver/factory/test’s “private” label. A global/default symbol is evidence of visibility/exposure, **not** proof of an actual second consumer; conversely, selected-function targets being in the selected closure do not prove table privacy.

## 2. Structural facts that can and cannot establish ownership (R0-safe)

### Confirmed model/parser boundary

- `ElfFile` exposes program headers, optional section headers, dynamic entries/metadata, `RelaRelocations`, RELR/Android relocation summaries, raw dynamic symbols, function symbols, bytes, and `LoadMap` (`src/UrProtect.Core/StructuralElf/ElfTypes.cs:565-629`). `DynamicSymbol` retains name offset, `Info`, `Other`, section index, value, and size (`:341-347`); the name is resolved through `ElfDynamicMetadata.StringTable`. `RelaRelocation` retains `Offset`, `Info`, `Addend`, `SourceAddress`, `IsPlt`, and derives type/symbol index (`:470-481`). `LoadMap` maps file/virtual addresses only through PT_LOAD file-backed extents (`LoadMap.cs:3-24,59-77`).
- `ElfParser.Parse` calls the dynamic RELA parser with `PT_DYNAMIC` entries and parses dynamic symbols (`ElfParser.cs:114-136`). `ParseRelaRelocations` reads only `DT_RELA` and `DT_JMPREL` (`:605-680`); its `Offset` is the relocated destination VA and `SourceAddress` is the RELA row VA. The parser does not parse `SHT_RELA` static-link relocation sections into `RelaRelocations`. Static symbol processing projects only nonzero-size `STT_FUNC` rows into `ElfFunctionSymbol` (`:895-928,931-1014`); there is no all-static-symbol/object model. No production `ElfStructuralIndex` implementation was found in the bounded `src/UrProtect.Core` search, although the design describes one.
- For a dynamic import, an undefined dynamic `STT_OBJECT` (`SectionIndex == 0`) plus its symbol-index-bound `R_AARCH64_GLOB_DAT` row can identify a loader-owned pointer slot. The existing external negative checker independently binds exactly that shape, the writable file-backed GOT slot, and selected-function GOT-load dataflow (`scripts/check-indirect-control-evidence.py:512-554`). The GOT slot is only the pointer carrier; it does not locate external table bytes or prove table support. This matches the backend evidence contract (`quality-guidelines.md:122-139`) and current PRD wording.

### Safe proof limits / inference

- **Selected-private:** the selected producer chain, proven bounds, bytes, and target closure prove that this selected dispatch reads this range. They cannot prove no other code/data/runtime reference exists. Absence of relocation/symbol hits is not a private proof because symbols/sections/relocations may be stripped or absent, and already-linked instructions/data can contain raw addresses. R0 forbids resolving that uncertainty by scanning all executable bytes/functions. Treat “private” as unproven unless there is a bounded, explicit complete-owner contract; do not infer it from one selected use.
- **Shared:** a positive structural reference from a distinct non-selected relocation site to the same table proves at least one observed additional user (provided the relocation’s linked symbol/addend and mapped site are validated). It does not prove the relocation inventory is exhaustive. A global symbol, a target outside the selected function closure, or a second table-shaped byte sequence is not itself proof of a second table user.
- **External/runtime-owned:** a demand-driven selected instruction chain bound to an undefined dynamic object’s exact GLOB_DAT/GOT slot establishes external loader ownership of that pointer source; a declared runtime binding can establish runtime-owned resolution. Missing relocation/owner information alone should remain **ambiguous/unresolved**, not be relabeled runtime-owned.
- **File-backed/table bytes:** a unique bounded read-only or writable file-backed PT_LOAD range, size, bytes, and virtual/file mapping prove the local storage range is readable from the source image. They do not identify who can reference it. Relocation destination slots, RELR, and dynamic GOT bytes must not be mistaken for the table itself.
- **Reference evidence needed:** for an exact compiler-built local shared fixture, retain section-linked static `SHT_RELA` symbol identity, relocation type/addend, source relocation-site VA, and the corresponding bounded table-base producer(s) for the selected function. The current parser has to add this structural support (or use a different already-supported positive proof source); a final stripped image with no such metadata stays ambiguous. Preserve the original table on ambiguity rather than mutating it.

## 3. Recommended smallest positive slice (Phase 2 items 10–12)

### Prerequisite split (do not create a task here)

1. **Owner/reference contract:** add an explicit `Ambiguous`/`Unproven` ownership state and typed owner-evidence records (source symbol identity/type/binding/visibility/range; relocation table kind/site/type/symbol/addend; selected table-reference producer/site bindings; coverage/completeness claim). Derive `Shared` only from positive additional-use evidence, `External` only from bound loader/import facts, and `RuntimeOwned` only from an explicit runtime owner. Keep an absent/incomplete relocation or stripped symbol case ambiguous. Add bounded static `SHT_RELA` section parsing/projected symbol resolution for the ET_DYN fixture if using `--emit-relocs`; preserve sectionless support through the existing data-flow path, but do not call it private merely because a symbol is missing. Do not add a full image decoder or make structural parsing depend on section headers.
2. **Copy/retarget layout contract:** teach the semantic snapshot/layout boundary a copy request that retains the source table, planned distinct output table range, source entry bindings, and exact selected-function reference sites. Add a bounded read-only output placement/materialization path (no writable/executable permission broadening), map the clone in `AddressMap`, re-encode the clone’s entries against output target/base mappings, retarget only the selected producer chain via typed semantic fixes, and prove the original table and unselected references remain byte/address-stable. The current in-place byte-edit contract is insufficient. If the implementation cannot produce a file-backed R-only clone and unique reference mapping, fail before publication.

This is a prerequisite split because the current implementation has no ownership input or copy semantics: merely changing the enum to `Shared`/`CopiedAndRetargeted` would either be rejected by the planner or risk editing the shared source table in place (`ElfLayoutPlanner.cs:2682-2688,2915-2920`).

### Preferred exact positive fixture and contract

- Add a native AArch64 ET_DYN assembly fixture, e.g. `host_context_shared_jump_table_fixture.S`, with one 4-entry signed-relative `.rodata` object explicitly declared as `GLOBAL DEFAULT STT_OBJECT`, selected `urp_entry`, and a separate unselected `urp_observer` using the same table. Both use bounded index checks and source target symbols; make the linker retain static relocation rows (`--emit-relocs`) for the table-base `ADRP`/low-12 `ADD` references. The table symbol/addend and section-linked relocation identities must resolve to exactly one source table range; the selected sites lie in `urp_entry`, and at least one additional site lies outside it. This makes the “shared” fixture proof concrete without scanning all executable code. A global symbol alone remains `Ambiguous`, not `Shared`.
- After protect/rehydrate, run the selected entry through every declared table index and verify its ordered results/status; separately invoke the unselected observer after transformation. Verify the selected dispatch was retargeted to a distinct mapped clone with all output entries mapping to output case addresses, the original table bytes are unchanged, and the unselected reference still reaches the original table/old code. Retain source/transformed handoffs and actual status/streams/target-selection evidence; independently parse the source symbols/relocations/table bytes and output clone/reference/entry bytes.
- The owner representation needs to distinguish **ObservedShared**, **SelectedPrivateProven**, **External**, **RuntimeOwned**, and **Ambiguous** (names illustrative). For each observed relocation/reference retain the source site, symbol-table identity/index and symbol binding/type/visibility, relocation kind/addend, mapped VA/file range, selected-function relationship, and whether the inventory is known complete. An incomplete inventory cannot emit `SelectedPrivateProven`. A source reference expression must bind each relevant ADRP/ADD or other producer, not merely the terminal `BR`.
- Clone consequences: source table remains untouched; copied entries are regenerated from each source target’s unique `AddressMap` output plus output target-base; the selected function’s table-address producer is redirected to the clone; unselected functions and external readers continue pointing to original storage. Target-base/entry signedness, scale, addend, alignment, range, and output PT_LOAD ownership are checked. Preserve source and output ranges separately in the canonical snapshot/layout evidence. Any retargeted AArch64 instruction is encoded/round-tripped through `Aarch64InstructionEncoder`, not a local bitfield writer (`quality-guidelines.md:38-49`).

### Independent nearest negatives

Keep these independent from the existing malformed/out-of-closure, checked-index-clobber, out-of-range, and external-import rows:

1. **Global-visible but no observed second user:** a global/default table symbol with one observed selected reference must remain ambiguous; assert the output does not claim `Shared` or `SelectedFunctionPrivate` from symbol visibility alone. Copy/preserve safely or fail closed; never edit the original as an assumed-private optimization.
2. **Conflicting/malformed relocation ownership:** mutate the section-link/symbol index, relocation type/addend/site, alias range, or selected producer-to-relocation binding so the reference no longer proves the same table. Require a deterministic pre-publication diagnostic and no Protected/Native Image, clone, or handoff. Refreshed metadata/checksums must not turn missing owner proof into a positive claim.
3. **Unselected source preservation:** mutate/omit one known non-selected table-reference row or make its source site overlap/alias the selected site; ensure the planner rejects incomplete/conflicting evidence or chooses a conservative policy, and never rewrites the shared original table.
4. **Copy/retarget bounds:** missing/ambiguous output mapping, non-file-backed or non-readable clone range, failed ADRP/ADD range/low-12 retarget, duplicate clone/table-entry binding, or signed entry overflow must fail before publication; verify no partially copied/rewritten output survives.

## 4. Explicitly open boundaries

Confirmed: the current PRD leaves ambiguous ownership open and scopes the independently reviewed external-table row to fail-closed behavior only (`.trellis/tasks/10-06-indirect-control-jump-tables/prd.md:48,52`). The promoted four-case native positive is glibc-only (`:49`); the evidence-spec rows require native runtime facts and separate negatives (`.trellis/spec/backend/quality-guidelines.md:83-139`).

Inference/recommendation: a global/default object’s visibility makes an unobserved outside reference possible, not proved; the safest positive behavior is clone-and-retarget the selected consumer while preserving the source table. If explicit relocation/reference data is unavailable, retain an ambiguous owner and do not call it private. A shared-table positive is not supportable in the current end-to-end architecture until the prerequisite owner/reference and copy-layout contracts are implemented.

Function-pointer support, other indirect-call strategy, musl/bionic runtime rows, TLS/CFI work, and parent-task completion remain open. No evidence root, manifest, acceptance checkbox, task status, production source, test, or fixture was changed; no build, test, native E2E, or evidence checker was run.
