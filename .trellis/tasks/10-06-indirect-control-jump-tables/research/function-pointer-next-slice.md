# Function-pointer / indirect-call next slice

**Scope:** read-only source/evidence research for child PRD criterion “Function-pointer and indirect-call fixtures exercise the declared static/runtime mapping strategy” (`prd.md:47`). No product, fixture, test, manifest, evidence-root, or task-status changes are made by this note.

## Recommendation

Add one narrow, compiler-built **static local function-pointer call** positive. The selected entry holds a volatile function pointer to a hidden, same-image `STT_FUNC`, calls it with `BLR`, and checks the result. Keep that target **unselected and preserved at its original source VA** in this first slice. Rebase the selected caller's ADRP producer to the preserved target page, bind the target to an explicit identity `AddressMap` mapping, and retain the BLR fallthrough under AAPCS64. Do not support a moved selected callee, opaque runtime pointer, general BLR, or veneer in this slice.

Keep the existing project-built `getpid` GLOB_DAT row as the separate **loader/runtime-owned** control. It already exercises a dynamic symbol/GOT binding; the proposed local callback exercises an exact static code target and preservation. These are different resolution modes and must remain different evidence claims.

## Source facts and candidate compiler-shaped fixture

`Aarch64IndirectCallProofAnalyzer` is already a selected-function, bounded CFG/dataflow pass: it starts from the selected decoded instruction list, caps the analysis at 65,536 instructions and 64 producers/value, merges facts over local CFG edges, and resolves each `BLR` from its incoming state (`src/UrProtect.Core/Aarch64Semantics/Aarch64IndirectCallProofAnalyzer.cs:30-141`). It already models ADR/ADRP-derived `ElfAddress` values and ADD/SUB arithmetic (`:432-520`), local stack stores and exact-size reloads (`:638-652,779-866`), and AAPCS call clobbers (`:226-231,990-1015`). But `TryProveCall` currently accepts guarded HostContext callbacks or validated imported GLOB_DAT function/NONE symbols only (`:1205-1339`); it does not turn an exact `ElfAddress` in the BLR target register into a static call resolution. `FunctionAnalysis.cs:350-367` consequently treats every other BLR as `IndirectTargetUnresolved` / incomplete.

A temporary toolchain probe (research only, outside the repository at `/tmp/urprotect-function-pointer-probe.vyn2gD/`) confirmed a small GCC-shaped case suitable for the new fixture. Probe source used:

```c
 typedef unsigned long uptr;
 typedef uptr (*callback_t)(uptr);
 __attribute__((noinline, used, visibility("hidden")))
 uptr callback_target(uptr v) { return v + 17; }
 __attribute__((noinline, used, visibility("default")))
 int urp_entry(void *context) {
     callback_t volatile callback = callback_target;
     uptr v = (uptr)context;
     return callback(v) == v + 17 ? 97 : 96;
 }
```

With AArch64 GCC 15.2, `-O1 -fPIC -fno-optimize-sibling-calls -fno-unwind-tables -fno-asynchronous-unwind-tables`, then `-nostdlib -shared --emit-relocs`, the linked ET_DYN/EM_AARCH64 emitted this compiler-shaped sequence in `urp_entry`:

```text
0x1e8 STP X29,X30,[SP,#-48]!
0x1f4 MOV X19,X0
0x1f8 ADRP X1, callback_target
0x1fc ADD X1,X1,#0x1e0
0x200 STR X1,[SP,#40]
0x204 LDR X1,[SP,#40]
0x208 BLR X1
... compare callback result with input+17; return 97 or 96 ...
```

The linked source ELF facts from the same probe are exact: `urp_entry` is dynsym index 2, VA `0x1e8`, size 64; `callback_target` is a defined `LOCAL STT_FUNC` in `.text` section 4 at VA `0x1e0`, size 8, entirely inside the executable file-backed PT_LOAD. `.rela.text` section 5 has `sh_link=13` (`.symtab`) and `sh_info=4` (`.text`); its two `urp_entry` rows at `0x1f8`/`0x1fc` are `R_AARCH64_ADR_PREL_PG_HI21` / `R_AARCH64_ADD_ABS_LO12_NC`, both symbol index 16 (`callback_target`) plus addend 0. The source has no dynamic relocation rows for this target. The probe also compiled an unselected `urp_observer` with the same stack-held indirect call to that target; its independent pair at `0x238`/`0x23c` names the same function symbol. `-fno-unwind-tables` kept this minimal path clear of an EH-frame/CFI dependency.

This is a research probe only—not a project fixture, a committed artifact, a project test, or runtime evidence. It demonstrates one reproducible ABI/toolchain-shaped implementation, not portability across all compilers. The project fixture should compile and link from checked-in C source with pinned flags, retain `--emit-relocs`, and independently assert its own final ELF bytes/symbols/relocations.

## Smallest safe vertical slice

1. **Target and ELF proof.** For one selected `urp_entry`, accept only a `BLR Xn` whose bounded producer/dataflow resolves to exactly one function address. Require the complete chain (ADRP + ADD + local stack store/load in the proposed compiler pattern), no conflicting writes/merges, and one matching section-linked relocation pair. Independently bind `SHT_RELA.sh_info` to the executable section containing the selected function/site; bind `sh_link` to the exact symbol table; bind both relocation sites, relocation type/addend, symbol index/name/type/section/value/size, and decoded address expression. Require the target to be one aligned file-backed executable range and the exact defined, non-preemptible `STT_FUNC` (`LOCAL` or hidden) identity. Reconcile the decoded address with the symbol value. Reject an unresolved/interposable target, missing/ambiguous static relocation pair, malformed `sh_info`/`sh_link`, stack slot mismatch, or an opaque BLR. Do not treat “no relocation” or missing section metadata as proof of static privacy.
2. **Separate static from runtime.** Introduce a typed exact-static indirect-call resolution/owner record; do not encode this as `Aarch64RuntimeIndirectCallResolution` or a made-up runtime binding. It should retain call VA/register, ordered producers, target symbol-table identity, source target VA/range, section-linked RELA identities, selected-target status, and explicit mapping policy. Existing `SemanticTarget` already distinguishes `Exact` from `RuntimeResolved` (`SemanticValueModels.cs:7-13,52-114`); retain that difference. The current `SemanticDynamicImportCallExtension` is deliberately a different full owner contract for undefined dynsym + GLOB_DAT + GOT range + call producer chain (`SemanticDynamicImportCallExtension.cs:25-150`).
3. **Transform policy for this first row.** Select only `urp_entry`; leave `callback_target` and `urp_observer` unselected. `urp_entry` moves to its protected output range, but the exact static target remains at original VA and gets an explicit identity/preserved target `AddressMap` binding. Re-encode the caller's ADRP to that original target page through `Aarch64InstructionEncoder`; retain the checked low-12 ADD immediate, stack round-trip, and BLR. The existing address-reference ADRP re-encoder is at `FunctionProtectionCodeEmitter.cs:998-1050`; the semantic PC-relative fixup/materialization path resolves through the physical map (`GenericRehydrationEngine.cs:1334-1432`). Keep BLR as a returning call and preserve its fallthrough adjacency as the runtime-call emitter path does (`FunctionProtectionCodeEmitter.cs:708-785`). Require the final ADRP displacement to encode; on range failure reject before publication. No veneer or runtime translation is needed or implied for this same-image nearby preserved helper.
4. **Do not overclaim target movement.** In this first slice, the helper is intentionally unselected and unmoved. The transformed observer remains at source code and still resolves the same helper. A static callee that is itself selected/moved is **not** covered: current `BuildIndirectSemanticSnapshot` explicitly permits exactly one selected function (`FunctionProtectionPlanning.cs:752-770`), and current `AddressMap`/fixup inputs do not establish a moved static function-pointer callee or its ADD-low12 fixup. Add that family only with one unique target output mapping plus encoder-backed producer rewrites and independent publication checks. If that map is absent/ambiguous, fail closed; do not assume source pointer values follow moved code. Stable-address veneers remain a distinct typed contract, not an implicit fallback.
5. **Native behavioral oracle.** Build the source C fixture as ET_DYN/EM_AARCH64 with `urp_entry(void *context)` matching the HostContext X0 argument, but never dereference the opaque context. The callback returns `context+17`; the entry compares the real call result to `context+17` and returns 97 (else 96). Run source and transformed `urp_entry` through the native HostContext loader, retaining source/Protected/Native Image hashes, producer/consumer records, actual handoff JSON, process/entry status, stdout/stderr bytes/hashes, and exact runtime identity. Also execute the unselected observer before/after and require the same status; independently check that observer code and callback target remain at source locations. Do not infer musl/bionic coverage from the current glibc host.

## Canonical snapshot and publication seams

- **Analysis:** `Aarch64IndirectCallProofAnalyzer.cs:1205-1339` is the narrowest extension seam; preserve its existing fail-closed bounded provenance behavior. `FunctionAnalysis.cs:297-367,515-532` needs a static resolution collection/CFG fallthrough distinct from runtime call resolutions. Do not change `BR`/jump-table matching or broadly accept unresolved `BLR`.
- **Emission/planning:** `FunctionProtectionCodeEmitter.cs:345-405,656-785` gates call classes; admit only a validated static resolution, and use its producer bindings. `FunctionProtectionPlanning.cs:278-455,752-840` builds owner extensions and the one semantic snapshot; extend it with the static owner and explicit source→output target mapping. Retain the currently supported one-selected-function bound for this slice.
- **Snapshot:** `SemanticIndirectTargetExtension` validates only target syntax, not source owner facts (`Aarch64SemanticPlanFactory.cs:93-123`; `SemanticPlanSnapshotValidation.cs:581-585`). `SemanticJumpTableExtension` has owner references and rewrite policy (`SemanticPlanExtensions.cs:35-170`), but its owner validator is specifically for `STT_OBJECT` table symbols, table-range containment, and table consumers (`SemanticPlanSnapshotValidation.cs:707-792`). Do not misrepresent a function symbol as a table owner; add a bounded typed static-call owner extension and canonical encode/decode/validation in the existing URP-SPS3 snapshot, no parallel snapshot/version decoder.
- **Publication:** rehydration already decodes exactly one canonical snapshot and independently validates dynamic import owners, dynamic call/output mappings, and jump-table section-linked owner references (`GenericRehydrationEngine.cs:343-403,549-700,702-880`). The dynamic-import validator checks every selected BLR has its instruction/address-map carrier and one indirect-target extension, but its complete source scan is specifically for imported GOT ownership (`SemanticDynamicImportCallContract.cs:335-535`); it is not a static function pointer proof. Add a static owner source-ELF validator that re-derives the SHT_RELA/symbol/bytes/dataflow facts and verifies the target AddressMap policy before Native Image publication. Keep fail-closed diagnostics: `IndirectTargetUnresolved` for missing/ambiguous producer or target proof; `SemanticPlanSnapshotMalformed` for forged/mismatched carried ELF owner facts; `SemanticAddressMapMissing` for absent/ambiguous output mapping; encoder/layout range errors for unrepresentable ADRP/fixup.

## Required nearest negatives

- Checksum-refreshed source-byte mutations for ADRP/ADD target mismatch, wrong target symbol/index/type/value/size/addend, altered `.rela.text` `sh_info`/`sh_link`, relocation site outside the selected function/section, or target outside executable file-backed PT_LOAD must fail semantic publication—not merely stale-hash checks.
- Clobber/replace X1 after the reload and before BLR; merge two different target addresses; remove the static relocation pair; or supply an input/runtime pointer rather than a statically proven function symbol. Each must remain `IndirectTargetUnresolved` before Protected Image/Native Image/loader publication.
- Mutate the emitted target mapping or forge the target as moved without one unique map; reject before publication. A changed ADRP page beyond range must fail rather than patch bits manually or silently preserve a stale pointer.
- Keep existing dynamic-import nearest negatives: undefined GLOB_DAT `STT_OBJECT` remains a non-callable target, wrong GOT/RELA/dynsym owner fails, and no provider/table payload is inferred. Keep existing external-table row as a fail-closed negative only.
