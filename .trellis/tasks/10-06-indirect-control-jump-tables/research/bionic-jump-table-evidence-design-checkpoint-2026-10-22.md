## Scope and boundary

Implement only ordinary relative jump-table and shared-table clone runtime evidence on the existing native AArch64 Termux/Bionic lane. Supervisor approved an evidence-only runtime identity extension and container bridge. Do not change the product loader/runtime behavior, HostContext ABI, runtime support matrix, or compatibility promotion.

## Evidence contract

- Keep the private native runtime identity carrier versioned independently from HostContext; Bionic uses the already defined schema-2 carrier and must keep `runtimeVersion: null` (no invented Bionic release string).
- Derive runtime identity from each live helper process: exact `/system/bin/linker64` interpreter, loader and libc mapped-file bytes, `/proc/self/maps` ownership, the existing Bionic SHA-256 fingerprint, and an evidence-only `runtimeEnvironment` containing the helper's `uname().release` and `sysconf(_SC_PAGESIZE)` observations. Independently validate retained bytes and strict path/root ownership in the Python checker.
- Bind the environment record to the existing pinned Bionic selection: `termux/termux-docker@sha256:e19ea56dd687563849826cbda57da714ae23277ee463e21f39917dbc0a59bab4`, Termux source commit `7033c7639eb86107a4fdf8b72bd6388c07b1284a`, and the full compiler-package lock in `fixtures/manifest.json`; do not pin transient kernel/page-size or host facts as fabricated constants.
- On this native, same-kernel container lane, producer and checker require host/container page sizes to be exact supported integer values (4096, 16384, or 65536) and equal; require bounded kernel-release tokens and exact host/container equality. Each retained per-handoff runtime identity must also match the recorded container kernel/page facts. Exact Python `int` checks reject booleans/floats.
- These are relational checks among retained producer observations and actual per-handoff helper observations, not cryptographic attestation. An actor able to coordinate changes to all self-reported facts and refresh all hashes can create a consistent alternate self-report; no stronger authenticity claim is made.
- Build all ordinary/shared fixtures and the handoff helper inside that image from the locked Termux compiler/linker/make packages. Preserve native build command/status/streams and require exact Bionic `PT_INTERP`; disable RELR for the controlled images. Execute helper handoffs through the image-bound container bridge, retaining source/target/observer identities and statuses under each evidence unit.
- The Bionic bridge treats its first positional argument as the pinned OCI reference and validates it against the locked selection. The retained source/transformed ELF is a separate argument and is validated/mapped under the isolated evidence/build roots; the OCI reference is never compared to an ELF pathname.
- Both evidence checkers validate the exact positive root, environment pin, runtime identities, source/transformed handoffs, and all existing jump-table range/ownership semantics. Bionic remains `not promoted`.

## Implementation checkpoint

The repository already contained the evidence-only Bionic carrier/checker and runner branches. 3. **P2 regression registration:** added exact ordinary and shared Bionic rows to `tests/regression-matrix.json`, with their producer and independent checker commands, native ARM64 container platform, PR/nightly/release tiers, bounded budgets, positive witnesses, and retained package/native/nested build-failure command/status/stream artifacts. 4. **P2 status/stream retention:** `capture-bionic-handoff.py` retains command, actual process status, stdout, and stderr before it parses the handoff JSON. Stub tests cover ordinary/shared transformed handoff failures, source handoff failure, absent/malformed success records, outer ordinary/shared build errors, and nested HostContext build diagnostics. They verify exact statuses/streams and that failed handoffs do not produce behavioral-oracle/closed positive evidence or reach downstream checking.
5. **P2 native-build status parsing:** all three Bionic runner branches now use the small owned `scripts/parse-native-build-status.py` parser before any `readelf`, handoff, or positive evidence publication. It opens with `O_NOFOLLOW|O_NONBLOCK`, requires a regular stable file bounded to 2..4 bytes, and accepts only canonical decimal `0..255` followed by exactly one LF. Missing, empty, truncated, symlink/nonregular, leading-zero, signed, whitespace, boolean-like, multiline, and overflow values fail closed. The command/stdout/stderr sidecars are copied before parsing; a canonical nonzero value is preserved exactly, while only exact `0` continues. Runner success checks use string equality (`!= "0"`), not Bash numeric coercion. Bionic runtime-environment evidence is copied into the positive root only after status parsing and the exact-zero gate. Executable tests invoke the actual ordinary/shared/nested runners and prove absent/zero-byte/malformed rejection before downstream tools or positive identity publication, exact-zero progress, canonical `37` propagation, exact status sidecars, retained streams, and no positive publication. The prior glibc/musl execution paths remain covered by their existing focused runner tests.
6. **Capture subprocess resource note:** the evidence capture helper still launches with `subprocess.run` writing directly to sidecar file descriptors; it has no per-handoff timeout or stdout/stderr byte cap. The current Bionic CI job has an enforced outer `timeout-minutes: 30`, but that is not a per-child stream bound. I did not add a process-supervision/stream-limit mechanism here: preserving actual child exit status and diagnostics across timeout/output-triggered termination needs explicit signal/timeout policy and separate tests/design. No forced termination is currently hidden or synthesized. Treat per-child output/latency bounding as a distinct follow-up if needed.
